# Независимое ревью R4: mobile-first Lab review queue

Дата: 2026-07-29. Ревьюер: Claude + три адверсариальных Opus-агента.
Автор ≠ ревьюер. Круги: R1 (7 блокеров) → R2 (NO-GO) → R3 (NO-GO) → R4.

Head-и (совпадают с SHA зелёных CI — проверено): backend `cfb499d`,
feed/TMA `4fdfa96`, generator `20e25fa`, agents `67fad8a`.
Ничего не мержилось и не деплоилось.

## Вердикт: **NO-GO**, но круг лучший из четырёх

Главное достижение: **класс «побег из песочницы» закрыт по существу**.
Артефакт больше не собирается в blob со сплайсингом — backend отдаёт байты по
короткоживущему signed URL с настоящим заголовком CSP (включая директиву
`sandbox`), TMA ставит `frame.src`. Проверено 56 векторами × Chromium/WebKit ×
3 режима родителя: **0 утечек**, включая redirect-laundering (302 на чужой
origin блокируется) и взаимное неослабление sandbox заголовка и атрибута.
Контроль без родительской meta даёт 6 попаданий — механизм рабочий, а не
совпадение.

Второе достижение: **инертность доказательств частично побеждена**. Из семи
фиксов, переживавших собственный откат в R3, пять теперь краснеют. В generator
мутационная батарея дала **11 из 11 убитых** — включая те, что R3 назвал
инертными. `Atomics.wait` убран не декларативно: контрольный замер тем же
методом — было 166 мс заморозки / 0 тиков таймера, стало 3.5 мс / 12 тиков.

Блокирует пять групп.

## Блокеры R4

### R4-B1 · P2 · Quirks вернулся третий раз (backend admission)
`app/mobile_review_service.py:175`: `html.lstrip("﻿\t\n\f\r ")` — U+FEFF не
является HTML-whitespace. Артефакт «пробел + BOM + doctype» **проходит приём и
рендерится в BackCompat** на обоих движках (измерено). Оператор одобряет
«exact»-прототип в раскладке, отличной от боевой. Заявление пакета «admission
again requires valid UTF-8 and the canonical doctype» не выполняется.
Побочно: NUL внутри HTML допускается (в JSONB запрещён), а валидные
`<!DOCTYPE html >` и `SYSTEM "about:legacy-compat"` отвергаются.
Фикс однострочный: убрать `﻿` из набора, требовать doctype сразу после
максимум одного ведущего BOM.

### R4-B2 · P2 · Верифицируются одни байты, исполняются другие (TMA)
Артефакт скачивается **дважды**: запрос №1 — `fetch` для SHA-256, запрос №2 —
`frame.src`. Второй не верифицируется ничем (`X-Content-SHA256` из iframe
принципиально нечитаем); собственный тест репозитория фиксирует
`previewRequests === 2`. Подмена байтов между запросами воспроизведена на
реальном собранном TMA: исполнились непроверенные байты, решение осталось
доступным (Chromium и WebKit).

R3 просил заголовок именно с формулировкой «тогда исполняемые байты равны
хэшированным». Заголовок получен — эквивалентность потеряна: она держится на
доверии к бэкенду (иммутабельная content-addressed строка + append-only
триггер), а не на проверке у клиента. Это допустимо как решение, но должно
быть **названо** решением, а не описано как «TMA verifies … then renders the
exact signed URL».

### R4-B3 · P2 · «Exact»-доказательство выдаётся, когда прототип не запускался
Обработчик `load` вызывает `onConfigured(...)` независимо от содержимого
фрейма. Измерено: истёкший тикет (403, TTL 300 c), заблокированный редирект
(пустой фрейм), снятый CSP-заголовок — во всех трёх случаях решение
предлагается оператору с `preview.configured = true` и точным дайджестом.
Обратная сторона: невинная перезагрузка фрейма движком (memory pressure в
Telegram iOS — штатный сценарий) читается как «попытка покинуть песочницу».
Плюс детектор обходится навигацией **до** первого `load` (R4-N4).
Минимум: не выдавать `configured` без положительной квитанции от самого
артефакта; `load` без квитанции считать неуспехом.

### R4-B4 · P2 · Рестарт навсегда убирает заказ с телефона (generator)
`G-R4-1`. Состояние публикации живёт в памяти; после рестарта оно `idle`,
идентичность подготовки вычисляется байт-в-байт как при первой попытке, бэкенд
идемпотентно реплеит уже терминальную строку — карточка не возвращается
никогда. Deny спасается случайно (там непустой `attemptId`). Это ровно класс
R3-B5/NEW-G1, достигнутый через рестарт, и NEW-G4 из R3, не закрытый, а
переродившийся.

Сопутствующее — `G-R4-2`, **прямое противоречие замороженному решению
оператора**: при 5xx/сетевой ошибке состояние остаётся активным, планировщик
шлёт `POST /api/catalog/publish` каждые 5 c — **~720 запросов в час
бессрочно**, оператору видно только `console.error`. Решение требует: «отказ
каталога обязан всплыть оператору, а не умереть в строке лога». Тест
кодифицирует текущее поведение как желаемое. Плюс риск повторной публикации,
если каталог зафиксировал publish, а ответ потерялся.
И `G-R4-3`: устойчивая ошибка `closeStaleCurrent` рвёт тик до применения
решений — ни одно решение с телефона не применяется, в списке проблем не видно.

### R4-B5 · P2 · Изоляция уведомлений: фантомы глушат реальные алерты (agents)
`A-N5`: новый класс `render_invalid` не добавлен в исключение
`realTransportSendsInWindow` (`dispatcher.ts:380`) — синтетическая
терминализация считается реальной отправкой. Измерено: бюджет = 1 при нуле
HTTP-вызовов; при малом лимите здоровый production-алерт получает
`breaker_ceiling`; flood-collapse терминально гасит следующую живую доставку.
На боевом конфиге (40/60 c) деградация начинается с первого фантома, полное
голодание достижимо (до 120 терминализаций за окно). Для `config_missing` тот
же инвариант **проверен тестом** — для `render_invalid` не реализован.

`A-N6`: после терминализации `enqueueProductionAction` находит строку по
`actionKey` без фильтра по статусу и возвращает `null` **навсегда** — пинг
человеческого гейта не переотправится никогда; зонд outbox считает только
не-терминальные строки, поэтому потеря невидима. Громкий затык заменён тихой
безвозвратной потерей.

## Остаточная инертность

| Зона | Состояние |
|---|---|
| generator | **11/11 убито** — претензия R3 снята полностью |
| agents | 10 из 12 мутаций краснеют; 2 новых гварда R4 добавлены без доказательств (один из них жёстко зашивает алфавит канала `[a-z]+`, из-за чего `prod2`/`ops-a` дадут `render_invalid` — и breaker-сводка, единственное сообщение, обязанное дойти, будет молча терминализована) |
| backend | **12 из 26 границ закреплены**. Покрытие `except DBAPIError` осталось 1 из 5 (как в R3); три из четырёх путей не защищены от возврата flush из `try`; гарды глубины, `parse_constant`, NUL-в-ключах, doctype и membership — инертны. Механика: тест doctype использует заведомо неверный дайджест, поэтому падает раньше проверки и проходит с обеими снятыми защитами |
| feed | 2 из 7 остались инертными, причём ровно та половина N3, что названа в находке («digest в ключе»): ключ переживает своё удаление, обнаружение даёт value-guard. Незакрытое поведение: возврат бандла к ранее отправленному дайджесту минтит новый `mutationId` — окно двойной отправки |

Отдельно: **drift-гард ORM↔миграции сравнивает модель саму с собой**. Доказано
прямо: литерал изменён **только в миграции** (32768 → 4096), поднята чистая БД,
прогнана вся приёмка включая PostgreSQL-набор — **52 passed**.

## Закрыто честно (принимается)

- Побег из песочницы (56 векторов, два движка, три режима) — и это главное.
- Чекбокс фабрики достижим реальным pointer-кликом на 390×760 и 375×667;
  регрессии используют настоящие pointer-события; мутация «вернуть sticky»
  краснеет. Цель «каждый шаг выполним с телефона» достигнута.
- Граница размера decision сошлась с PostgreSQL **байт-в-байт** (фаззинг на
  400 документах, 0 недооценок); `CheckViolation` ловится раньше
  `IntegrityError` → 422 вместо ложного 409.
- Тест гонки открывает реальное окно внутри advisory-лока и детерминированно
  краснеет при выключенном локе (3/3).
- Deny больше не выбрасывает заказ; crash-loop исчез; терминальный отказ
  каталога виден; счётчик действий починен; `Atomics.wait` убран с замером.
- Глубина JSON режется ровно на 65; тело 422 не содержит присланный документ
  (проверено на 17 командах + 8 сырых телах).
- agents: A-N3 закрыт выбором «исправить контракт» — синхронно переписаны
  четыре места; изоляция снимает head-of-line для тегированных ошибок;
  транзиентные по-прежнему ретраятся.

## Минимум для пятого круга

1. R4-B1: убрать `﻿` из `lstrip`; принять валидные формы doctype.
2. R4-B2: либо не скачивать дважды (один запрос, из него и хэш, и рендер —
   например `srcdoc` с CSP-заголовком не нужен, если байты уже проверены), либо
   явно записать «эквивалентность байтов обеспечивается иммутабельностью
   хранилища» как решение и убрать из пакета формулировку про верификацию.
3. R4-B3: `configured` только по квитанции от артефакта; `load` без квитанции —
   неуспех; отличать перезагрузку движком от навигации.
4. R4-B4: восстановить идентичность после рестарта (persist attemptId или
   включить в идентичность что-то, переживающее рестарт); ограничить ретрай
   планировщика и вывести отказ оператору (этого требует замороженное решение);
   не ронять тик на `closeStaleCurrent`.
5. R4-B5: добавить `render_invalid` в исключение бюджета (там же, где
   `config_missing`) и обновить докстроку; терминальная строка не должна
   блокировать повторную постановку пинга; заменить allow-list кодов на
   ограниченное число попыток для любой ошибки рендера.
6. Инертность: backend — довести до состояния generator (сейчас 12/26);
   feed — тест «дайджест A → B → снова A ⇒ реплеится исходный mutationId» и
   close-page/new-page вместо reload; agents — покрыть два новых гварда и
   расширить алфавит канала.
7. Drift-гард: сравнивать миграции с моделью (`compare_metadata`), а не модель
   с собой.

Порядок включения после зелёного круга не меняется. Выдача
`operator.review:write` и переключение прод-уведомлений остаются операторскими
гейтами.
