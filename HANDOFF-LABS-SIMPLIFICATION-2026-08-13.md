## 0. Суть инициативы в одном абзаце

Упрощение операторской консоли Lab (swipe-generator) вокруг одного
пользовательского пути: **Telegram → открыть нужный объект → сразу понять
статус → проверить → принять решение**. Пять слайсов: телефонный inbox →
честные статусы → скорость отсмотра → «три комнаты» → единая очередь и
диагностика. Канонический scope, порядок, оценки и критерии приёмки — в
`docs/lab-simplification-plan-2026-08-13.md` (**v2.2 — единственный
авторитетный документ scope**; этот handoff его не заменяет и при
противоречии проигрывает ему и STATE.md).

8. Никаких прод-актов: publication, activation, mapping, catalog, roster,

## 7. Процессные правила (two-Mac, сжato)

- Durable ticket в meta-репо обязателен перед PR/candidate/merge; локальный
  spike и `wip/*` — можно без тикета.
- Review ladder: bounded Labs code = **один** blind cross-provider раунд
  (автор — эта Codex-сессия → ревьюер Claude Opus 5, effort `high`);
  discovery-партия → все P1/P2 разом → один узкий delta-verification.
  P3 не блокируют. Frontier (Fable) — только исключительная эскалация.
- Receipts живут в Issue/PR/task output; в корень meta-репо — только
  canonical outcome. STATE.md читать первым, обновлять последним; лимит
  150 строк — не раздувать.
- `NEEDS_HELP` сначала триажит оркестратор; самостоятельно не чинить чужие
  контуры (например, notification recovery Pins из пункта 0 — не твоё).
