## Вердикт: GO на shadow-сборку. Все 3 моих P2 и все рекомендованные P3 закрыты — конвергентно и радикальнее, чем просил.

- **P2-1 (истинность evidence)** — закрыто сильнейшей формой: LLM в
  факт-плоскости вообще не пишет значений, только выбирает цитаты
  `{kind, ref}`; валидатор разрешает ref против exact manifest И сам
  рендерит значения из байтов. Подделка фактов невозможна физически, не
  «запрещена». Числовые лимиты заморожены, multipart запрещён (рвал бы
  reply/remember-привязку).
- **P2-2 (петля Q&A-истории)** — закрыто радикально: история удалена из
  контекста целиком (K=0 в qa-policy), continuity только через
  одобренный журнал, негативный тест «такой контекст не собирается» +
  оба корпус-класса.
- **P2-3 (честность value-scan + некликабельный рендер)** — закрыто как
  канон: несущая защита = plain text без parse mode с выключенным
  preview; NFKC + запрет bidi/zero-width/control; построчные префиксы
  плоскостей мнения с экранированием маркеров (анти-спуфинг заголовков);
  скан по итоговому отрендеренному тексту и честно понижен до
  вспомогательного.
- Мои P3: fingerprint = qa:<qaRequestId> (коллизия одинаковых вопросов
  исключена идентичностью классификации); quota-отказы bounded (3/день,
  дальше только классификация); /ask только в digest-чате + отдельный
  logical-канал `qa` со своим бюджетом; /remember резолвится через
  delivery-цепочку детерминированно; усечение журнала — в receipt.
- Отдельно отмечаю два решения строгого пакета как правильные и
  поддержанные мной: **граница фазы A** (attended `qa:drain`, авто-цепочка
  = B1 с полным списком гейтов; graduation недели её не двигает) и
  **reply-identity** (`allow_sending_without_reply=false`, удалённый
  вопрос = терминал). Четыре замороженных контракта (§4/§6/§7/§8)
  исполнимы как написаны.

## P3 — три однострочные правки (можно при реализации, проверю на CR)

1. **Операторская видимость несчастливых исходов**: после «вопрос №N
   принят» ветки `validation_failed` (кроме overflow — у него отказ
   есть), `failed_terminal` и `expired` не обещают оператору никакого
   уведомления — вопрос молча умирает (в фазе A смягчено attended-drain,
   в B1 станет заметно). Добавить: терминальный исход ⇒ bounded
   шаблонный notice в qa-канал (кроме question_deleted — там reply
   некуда).
2. **Supersede без операторского пути**: поле `supersedes?` и
   partial-unique head есть, но команда, которой оператор выражает
   «замени инсайт X», не специфицирована. Либо `/remember <n>
   supersedes <handle>` (и manual-вариант), либо явно убрать supersede
   из v1-команд (lineage останется schema-ready).
3. **Усечение журнала видно только в receipt**: дешевле всего — строка в
   `/insights`: «в контексте N из M активных» (receipt остаётся точным
   источником).

Заметка без действия: overflow-отказ расходует слот квоты (резервация до
триггера) — поведение по построению, при cap=10 приемлемо.
