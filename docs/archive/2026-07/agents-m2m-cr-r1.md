# Code review: ветка `agents-m2m-read` (5 коммитов, HEAD `cb56584`) против спеки v2.5

Дата: 2026-07-19. Ревьюер: внешняя линия. Прогон ревьюера: 32 pure passed +
31 PG-gated skip (воспроизведено лично), 728 существующих без регрессий
(по отчёту исполнителя). Дифф строго в 13 заявленных файлах, чужие
ручки/тесты не тронуты.

## Вердикт: GO на push/CI/merge после двух маленьких P2. P1 нет.

Governance: спека в ветке = v2.5 (r4–r6 со строгим ревьюером во время
реализации; мой GO был на v2.2). Проверил changelog §11b–§11d — раунды
легитимные, закрывали реальное (изоляция revoked от sibling-ёмкости,
seal-протокол `clock_timestamp()`, NULL-коалесценция, раздельная формула
summary); моё замечание о bound `rate_limited`-строк вошло в v2.3.
Ревью реализации выполнено против v2.5.

### Подтверждено лично ревьюером
- Zero-DB admission — правда: бакет первым (`agents_m2m.py:366`), сессия
  ленивая, конвертные проверки (≤256, схема, regex) до lookup'а.
- Bound per-request строк revoked/rate_limited = K (дефолт 5) через
  атомарный `RETURNING count` window-upsert'а — audit-строка в той же
  транзакции при ordinal ≤ K.
- **Интерпретация failed-lookup budget ПРИНЯТА**: unknown_token-счётчик
  denial-window = сам бюджет (один upsert фиксирует отказ и решает
  401-vs-429). Адверсариальная проверка: (а) admitted unknown-запрос =
  ровно 3 DB-операции (lookup + upsert + finalize-CTE), суммарно bounded
  admission-ёмкостью; (б) семантики не смешаны — анонимный 429 живёт под
  `unknown_token` только в denial-потоке, enum/CHECK'и аудита не задеты;
  (в) страгглер через границу окна ретаргетится новой транзакцией по
  `clock_timestamp()`, дельта не теряется. Операторская заметка: слой 2 —
  семантический гейт (429 vs 401), НЕ экономия DB-операций; БД защищает
  слой 1 — это соответствует спеке.

### Подтверждено агентами (двойной срез)
Миграция 0046 ↔ models.py без расхождений; `NULLS NOT DISTINCT` ровно на
двух denial-уникальностях (у active-name — partial-предикат, корректно);
триггеры append-only/иммутабельности/`sealed`-latch/no-DELETE на месте;
guarded downgrade в стиле 0044/0045. Wire-контракт §6 буквально исполнен:
pre-assigned audit_id, digest только от body, allowlisted-заголовки
включая сам X-Agents-Audit-Id, commit до отправки ровно того буфера, 503
без audit-id и тела, error_fingerprint по замороженной канонизации, 422
аудитируется корректно. Секретов/токенов в диффе и логах нет; runbook
покрывает §10 целиком; CI-леги (acceptance autodiscovery + migration
matrix) зарегистрированы; DB-op-счёт flood-теста — настоящий
`before_cursor_execute`, не прокси.

## P2 — закрыть до merge (оба точечные)

1. **Flood-recovery ассерт отсутствует** (§9 мандат: «после спада флуда
   валидный путь восстанавливается»). `test_flood_of_unknown_tokens_…`
   меряет bound DB-операций и наличие 429, но не доказывает
   восстановление валидного credential после спада. Дописать хвост теста:
   спад → refill admission → валидный запрос → 200.
2. **Admission-429 невидим** (§6 мандат: «структурная лог-строка
   per-worker» — единственная наблюдаемость слоя 1; §3 признаёт lockout
   легитимного агента). Сейчас ветка `:367` молчит — оператор не отличит
   «флуд отсекается» от «агент заперт». Одна структурная лог-строка
   (worker, capacity, drop-счётчик с собственным rate-limit'ом лога).

## P3 — по усмотрению (рекомендую №1 и №2 до merge, остальное после)

1. **§5-отклонение**: машинные ручки зовут HTTP-хендлеры человеческих
   ручек напрямую с `_=None` вместо «внутренних функций чтения, не
   HTTP-ручек». Функционально изолировано, но наследует будущие
   side-effects хендлеров. Экстрагировать чистые read-функции ИЛИ
   зафиксировать отклонение строкой в спеке.
2. Flag-off: маршруты отсутствуют в app.routes/OpenAPI (тест есть), но
   запрос к выключенному приложению на 404 не дёрнут — однострочный тест.
3. Revoke-vs-use — только последовательный тест; конкурентной гонки по
   критерию линеаризации §4 нет.
4. Event-driven финализация не заассерчена (served-запрос/GET реально
   запечатывают чужое окно); конкурентные finalizer'ы на summary
   `ON CONFLICT` не гоняются; retarget-on-sealed ветка без dedicated
   теста (lock-blocking вариант покрыт).
5. RFC 7235: схема сравнивается регистрозависимо (`:375`) — сравнить
   case-insensitive или зафиксировать exact-match в спеке.
6. Swallowed handler-5xx без логирования traceback (диагностируемость);
   мёртвая константа `RESPONSE_HEADER_ALLOWLIST` (риск дрейфа с ручным
   allowlist'ом в wire-обёртке — свести к одному источнику);
   `finalize_denials` на каждом отказе (надмножество спеки, только
   эффективность); PG15/PG16 разнобой в докстрингах миграции;
   trailing-slash 307 на admin GET; 503-тест мокает writer, а не
   инжектит реальный DB-fault.

## Условие merge
Два P2 → мой быстрый diff-чек → push ветки → CI PG16 (24 acceptance + 6
migration gated-тестов — финальный гейт вердикта, как условлено) → merge
→ deploy (default-off, безопасно во время A1-недели). Эти P2 не требуют
нового полного раунда.
