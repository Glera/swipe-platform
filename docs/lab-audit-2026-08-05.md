## 1. Вердикт

Lab жив и цел: **обрывов проводки нет** — двойная сверка 1:1
(клиент ↔ Lab-сервер ↔ бэкенд, включая все 9 имён грантов и поля
recall-команды). Инженерное качество высокое, покрытие местами образцовое
(series orders: 2226-строчный UI-сценарий). Но операторская скорость
съедается тремя вещами:

1. **Тяжёлый polling-конвейер** — самые дорогие маршруты крутятся раз в
   5 секунд и в пути сохранения вердикта (§4).
2. **Молчаливый/технический фидбек на самых опасных кнопках** — двойной
   запуск кампании тратит реальные деньги, ошибка активации прод-ленты
   выглядит как успех (§5).
3. **Слепые зоны без тестов** — voice, панель доставки, merge-art publish,
   плюс три системных ловушки конфигурации (§6).

## 2. Карта функционала

12 вкладок SPA (`public/lab.html`, монолит `lab.js` 5802 строки + 5
модулей; сервер — ручной роутер `src/server.mjs` + ~90 модулей):

| Вкладка | Назначение |
|---|---|
| Очередь | форма кампаний генерации, reference evidence, lanes/runs, панель доставки QA-оценок в каталог |
| Прототипы | sandbox-миксы механик со своим отсмотром |
| Заказы | главный конвейер: заказ серии → фабрики → мир → уровни → сборка → публикация |
| Отсмотр | слепой отсмотр (уровни/скины/серии/эксперименты), голос, rework-врезка, merge-art publish |
| Доработка | immutable rework-циклы (level + experiment) |
| Помеченные | полевые пометки из прод-ленты + C1-карточка + dismiss/rework/recall |
| Каталог | read-only браузер + «личный тест в ленте» + recall entry |
| Композер | состав/порядок встроенных механик прод-ленты (DnD + CAS-активация) |
| Числа ленты | sequencing-консоль: slate + пилотные числа |
| Уровни | Level Library + ручная деривация LevelSpec |
| Серии | Workshop: ручная сборка серии + публикационная модалка |
| Память | read-only контекст вкуса |

Вне UI (в отчёты почти не попадает, найдено верификатором): jobs-API для
CLI-фабрики; **третий публикационный путь** `scripts/catalog-series[-batch].mjs`;
операторские recovery/transfer/import-скрипты; launchd-инсталляция
(`scripts/service.mjs`); фоновые серверные циклы (rework/delegation/delivery
тики); `POST /v1/series-previews/…/completions/{id}` — receipt exact-прохождения
серии (гейт series-good).

## 4. Перфоманс: где оператор ждёт зря

Существующий контракт `npm run lab:performance` меряет латентность 8
захардкоженных путей — **ни одна находка ниже им не покрыта**.

**P1 (подтверждены верификатором построчно):**
1. `GET /v1/operator-flags` на каждый вызов пересобирает индекс каталога
   **до 20 последовательными** сетевыми страницами + полный levelLibrary +
   мутирующий reconcile на GET — и это в 5-секундном поллинге
   (`server.mjs:509-514,1885-1897`; `lab.js:5786,5797`). Лечение:
   серверный кэш проекции (TTL 30–60 с), reconcile в фоновый тик, интервал
   30 с + guard `document.hidden`.
2. Каждый HTTP-запрос series-preview (host каждого уровня и **каждый файл
   рантайма**) заново резолвит всё замыкание серии, включая QA-детей
   **всех** levels-джоб корпуса; `no-store`
   (`series-preview.mjs:301,250-257,119-122`). Это гейт series-good —
   стоимость растёт с каждым ночным прогоном. Лечение: кэш кандидата по
   `${draftId}:${revision}` (ревизия иммутабельна), выборка QA-детей только
   нужных джоб.
3. Каждый ассет level-preview — полный resolveCandidate + sha256 всех байт,
   `no-store`: отсмотр 25 уровней одного батча = 25 перекачек и
   перехеширований одного бандла (`level-preview.mjs:457,488-489,130`).
   Лечение: ETag=digest из манифеста + `immutable`, верификация байт при
   прогреве, мемоизация resolveCandidate.
4. `GET /v1/reworks` — многоуровневый N+1 по файловому стору под локом, и
   он **синхронно ждётся в пути сохранения вердикта** перед искусственной
   паузой (`rework-store.mjs:1585-1605,999-1013`; `lab.js:5324`). Лечение:
   один проход по стору + кэш по revision + в submitReview точечный запрос
   вместо полного refresh.

**P2:** пауза 420 мс на каждый вердикт (`lab.js:5335`); boot-waterfall
(тяжёлый `/v1/lab` сериализован перед четырьмя тяжёлыми вызовами, которые
и так дублируются в setView; `lab.js:5769-5789`); preflight-цикл до 30×
полный `/v1/lab` с частотой 1 Гц (`lab.js:4053-4064`); N+1 в списке заказов
с TTL-кэшем 1 с (`series-order-service.mjs:2120-2136`); двойной refresh
после каждого действия над заказом при уже полученном detail
(`series-orders-ui.js:1522-1529`); poll каталога сбрасывает пагинацию к 25
записям (`lab.js:2609`); `setInterval` без `document.hidden`
(`lab.js:5790-5802`); нет prefetch следующего кандидата отсмотра
(`lab.js:4822`); `renderReworks` — полный innerHTML неограниченного дерева
на каждый тик (`lab.js:5091-5159`); обход levelReviewBaseCache
(`lab-service.mjs:442-444`).

**P3:** N+1 evidence в pendingExperimentStarts; poll-ответ тащит статичные
каталоги механик/моделей без ETag.

После фиксов — расширить `lab:performance` этими маршрутами, чтобы не
отрастало обратно.

## 5. Фидбек: 16 нарушений, 6 образцов

**Самое тяжёлое — необратимые действия без обратной связи:**
- «Сохранить и запустить сейчас»: ни guard, ни disable, POST без
  идемпотентности — **двойной клик = две кампании и двойная трата на
  модели** (`lab.js:5523-5530,1189-1194`; `server.mjs:2085-2088`).
- Модалка активации ростера прод-ленты: кнопки не учитывают busy, «Отмена»
  открыта во время полёта, **при ошибке модалка закрывается как при
  успехе**, тост не показывается, след — абзац за пределами экрана
  (`lab.js:3138,3491-3532`; `lab.html:296`).
- «Применить» в консоли секвенсора — та же болезнь на операции «остановит
  планировщик для всех» (`sequencing-console-ui.js:388,538-570`).
- Recall entry из «Помеченных» — busy без перерисовки: во время
  деструктивного отзыва на экране ничего не меняется (`lab.js:3952-4014`).

**Системные слои:** единственный канал — серый тост 11px, `role=status`,
автоскрытие 2.8 с, успех неотличим от ошибки (`lab.js:139-147`); ~20 мест
`toast(error.message)` с сырыми серверными строками (`server.mjs:2373-2378`
отдаёт наружу любой `error.message`); формы теряют ввод: recall-форма
каталога стирает набранную причину при busy/409 (`lab.js:2736`), ошибка
«Ещё» затирает весь список (`lab.js:2615`), receipt активации ростера
исчезает при любом перетаскивании (`lab.js:3437-3466`).

**Образцы, которые уже есть в коде и которые надо тиражировать:**
`beginBusy/progressMarkup` из series-orders-ui (спиннер + человеческий
заголовок + пояснение, aria-live); именованные фазы публикационной модалки
(ошибка остаётся в модалке); пять таблиц «код → человеческая фраза с
подсказкой действия»; панель доставки (один производный busy на всю
панель, словесные состояния); паттерн «выключено → скажи почему» у
recall; `describeDeferredRun` (заголовок + причина + время + «ничего
нажимать не нужно»).

**Рецепт:** общий `withBusy(button, label)`, общий `humanizeError()`
(свести пять существующих таблиц), `toast(message, {kind})` с
неисчезающими ошибками, «модалка не закрывается при ошибке», сохранение
ввода при перерисовке.

## 6. Работоспособность

Сильно покрыты: series orders, Workshop/publish, roster composer, catalog
recall, rework, level review, ядро catalog browser.

**Слепые зоны (ноль тестов):** клиентская запись голоса и вся локальная
транскрипция (Apple Speech → whisper.cpp, resume после рестарта); UI-панель
доставки каталога; merge-art publish на уровне HTTP; reference evidence UI;
форма кампании (`PUT`, `/run`, cancel); фильтры/пагинация каталога; UI
Level Library. `test/lab-ui-skin-review.test.mjs` — regex по исходнику, не
поведение.

**Системные ловушки:**
1. Единственный реальный HTTP→PostgreSQL E2E секвенсор-консоли и guard
   дрейфа backend-голденов **оба skip в CI** — автоматической защиты от
   рассинхрона контрактов нет (вручную сверено: дрейфа сейчас нет).
2. Вкладка «Помеченные» **падает целиком**, если роут аналитики недоступен:
   `operator-flags-lab-client.mjs:588` безусловный throw при не-200 — а
   бэкенд гейтит flags и analytics независимыми флагами.
3. Все шесть backend-контуров Lab включаются **одной** переменной
   `SWIPE_CATALOG_BASE_URL`, бэкенд — независимыми флагами: выключенный
   флаг выглядит в Lab как «включено, но нет данных» (404 маскируется).
   Частный случай: `/changes` секвенсора при выключенном apply-флаге даёт
   404 → «request was rejected».
4. `lab.js:2785` хардкодит `https://swipe-platform.onrender.com/` для
   обложек/оверлея композера; хук `__SWIPE_PLATFORM_BASE__` никем не
   устанавливается, серверный `SWIPE_PLATFORM_ORIGIN` на это не влияет.

**Чек-лист ручного прогона (сжатый, по one-liner на контур):** серия
3 уровней до publish-initiate без Telegram-подтверждения (Cancel/Deny);
повторная публикация той же ревизии (ожидается replay/409); recall с
устаревшим epoch (409 + префилл) и replay той же mutationId; derive с
невалидными targetStacks (внятная ошибка); фильтры+«Ещё» каталога (курсор
без дублей); активация ростера дважды с одной mutationId (replay);
«Помеченные» только с flags-грантом (понятна ли причина); голосовой
комментарий до готовой расшифровки + рестарт Lab с незавершённой;
доставка оценок до pending=0; полный `npm run verify` под node 24 (машина
сейчас на node 26 — вне engines).

## 7. Вкус и стратегия (frontier-слой)

**Три рабочих места вместо 12 вкладок.** Lab сейчас — пульт инженера:
12 вкладок отражают 12 подсистем, а не жизнь оператора. Оператор живёт
тремя ролями: *утренний отсмотр* (вкус), *ведение конвейера* (заказ →
публикация), *надзор за продом* (каталог/ростер/числа/пометки). Предлагаю
три режима-«комнаты» с текущими вкладками как подэкранами. Это же снимет
половину дублей из §3 (recall, rework-входы, setting-output).

**Целевая метрика UX — время между двумя вердиктами.** Утренний отсмотр —
главный цикл, каждая секунда умножается на 25–50. Сейчас между вердиктами:
сеть (P1 №4) + 420 мс + холодный iframe (P2). Целевое состояние: вердикт
клавишей → следующий уровень уже прогрет (prefetch) → руки не покидают
клавиатуру (J/S/L/B уже есть — отличная база). Это самая рентабельная
инвестиция во всём Lab.

**Прод-хирургии — торжественность, рутине — скорость.** Активация ростера,
числа ленты, recall, publish — редкие и опасные: там уместна модальная
церемония с diff и последствиями (соответствует контуру «ядро» — вторая
подпись через Telegram Approve уже есть и это правильно). Ошибки там
должны быть громкими и остающимися. Рутина (вердикты, фильтры, обновления)
— наоборот, неблокирующая и мгновенная. Сейчас перепутано: опасные кнопки
молчат (§5), рутина ждёт (§4).

**Единый центр допусков.** Шесть Telegram-грантов = шесть одинаковых
карточек, разбросанных по вкладкам (в композере — вообще под рабочей
областью). Одна панель «Допуски»: статусы всех грантов, продление, и
диагностика ловушки №3 из §6 (показывать, какие бэкенд-флаги реально
отвечают).

**Язык.** Интерфейс наполовину русский, наполовину техно-английский
(«Recall committed», syncDisposition, «HTTP 500»). Операторские поверхности
довести до полностью человеческого русского; машинные коды — в мелкий
receipt-шрифт. Таблицы перевода уже есть — нужен только общий каркас.

**Против вижена.** VISION §6 («инструменты дешевле кормят вкус, а не
заменяют его») Lab уже выполняет архитектурно — узкое место воронки
50 spec → 25 pass это скорость и комфорт вкусового решения, то есть §4+§5
этого аудита напрямую конвертируются в пропускную способность контента.
Мобильный контур (mobile-series-order-review, замороженный контракт) —
правильное направление: утренний отсмотр должен уехать в телефон, и
desktop-Lab это подтверждает своей перегруженностью. Для P4G Stage 2
ничего закладывать не нужно, кроме дисциплины «новые поверхности — в
комнату Конвейер, а не тринадцатой вкладкой».

## 8. Бэклог (волны, каждая — bounded-задача для исполнителя)

- **Волна 1 — скорость отсмотра:** убрать 420 мс из пути вердикта;
  точечный запрос вместо refreshReworks в submitReview; prefetch
  следующего кандидата; ETag/immutable на ассеты level/series-preview;
  кэш кандидата серии. *Эффект: время между вердиктами ↓ в разы.*
- **Волна 2 — честный фидбек:** withBusy на save-run / activate / approve /
  recall / dismiss; humanizeError; toast с kind и неисчезающими ошибками;
  модалки не закрываются при ошибке; сохранение ввода recall-формы.
  *Эффект: закрывает и денежный дубль кампаний.*
- **Волна 3 — гигиена:** кэш operator-flags + интервалы 30 с +
  document.hidden; выпил мёртвого (§3); слияние recall-поверхностей;
  центр допусков.
- **Волна 4 — страховки:** голден-дрейф и E2E секвенсора в CI (чекаут
  сиблинга по расписанию); починить `__SWIPE_PLATFORM_BASE__`; деградация
  «Помеченных» без аналитики вместо падения + тест.
