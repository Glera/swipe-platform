# Бесконечный поток любимой механики — v0

- Дата: 25.08.2026. Статус: продуктовое решение зафиксировано оператором в
  чате («на старте достаточно бесконечного потока»); реализация — очередь
  платформы после hands-free пакета.
- Цель v0: игрок с любимой механикой никогда не упирается в «контент
  кончился». Разнообразие — отдельная необязательная струя, не условие
  бесконечности.

## Решение v0 (минимальный состав)

1. **Два класса контента.**
   - *Новизна* (новый вариант/твист/арт): Labs + операторский вкусовой
     Approve — как сейчас.
   - *Рефилл утверждённого варианта*: без ручного гейта. Approve варианта —
     вкусовая авторизация всего его параметрического семейства. Гейты
     машинные: solvability, конверт сложности, дедуп по
     `(fingerprint_version, series_fingerprint)`, ревалидация
     manifest/LevelSpec/runtime-замыкания (всё уже существует в аллокаторе).
2. **Гарантия = floor.** Для (игрок, любимая механика) сервер держит «впереди
   ≥N невиданных серий» в персональном runway. Просадка → авто-запрос рефилла
   фабрике (deterministic seed → серии LevelSpec → машинные гейты → catalog
   admission → runway). Фабрика недоступна/медленна → существующий safe
   fallback замороженной continuation-цепочки. Дедуп исключает повторную
   выдачу виденного.
3. **Сложность v0:** фабричная монотонная кривая с периодическими
   передышками, объявляемая генератором. Без per-player адаптации.
4. **Future-proof бесплатно (единственная уступка будущему):** каждая
   сгенерированная серия несёт метаданные у истока —
   `{mechanicId, variant, seed, generatorVersion, difficultyCurve}`
   (+`featureTags[]` опционально, если генератору они и так известны).
   Разметка при генерации бесплатна; ретроспективная — дорога.

## Сознательно отложено (включаем по мере роста, отдельными решениями)

- Satiety-сигнал усталости (тренд completion/skip/dwell) — сперва shadow.
- Skill-бакеты per (игрок, механика) из существующего results-wire и окно
  сложности для ветеранов.
- Выбор по невиданным `featureTags` («новое разнообразие, которого он ещё
  не видел»).
- Probe-слоты возврата уставшей механики при появлении нового approved
  варианта (+cooldown).
- Демандный заказ разнообразия для Labs от исчерпания тег-пространства
  когортой ветеранов.

## Границы

- Замороженная continuation-цепочка v1 не меняется: всё новое — входы в
  существующий slot decision и его immutable sidecar (объяснимость каждой
  выдачи сохраняется).
- Hard-гейты включения (`capabilities.levelSeries=false`, manifest-bound E2E,
  production bootstrap, device/event-order, p95) остаются в силе — v0 их не
  обходит, а проходит.
- Пилот: одна механика с самым надёжным параметрическим генератором, один
  утверждённый вариант end-to-end до runway.

## Инварианты v0 (операторское уточнение 25.08)

1. **Рефилл — общий пул, не пер-игрок.** Фабрика держит запас серий по оси
   `(механика, approved-вариант, difficulty band)`; персональным остаётся
   только фильтр «этот игрок уже видел» (существующий dedup по
   `series_fingerprint`). Стоимость генерации не масштабируется как
   `игроки × генерация`. Low watermark считается по перцентилю unseen среди
   активных любителей механики (не по размеру пула): рефилл общий, дно
   персональное.
2. **Approve семейства — с точным пином.** Вкусовая авторизация привязана к
   `{variant, generatorVersion, разрешённый диапазон параметров, difficulty
   envelope}`. Новая версия генератора или расширение диапазона/конверта —
   новый Approve; новые seed внутри одобренного конверта — автоматический
   рефилл. В v0 строго: любой новый `generatorVersion` = новый Approve.
3. **Hard/soft-гарантии разделены.**
   - hard: любимая механика всегда доступна — лента не пустеет;
   - normal: сначала только невиданные серии;
   - degraded: при исчерпании/аварии фабрики допускается безопасная
     continuation/replay; факт replay помечается в decision context
     (sidecar), чтобы экономические правила (qualified-play, позже
     mission-вклады) видели повтор — правило наград за replay отдельное
     существующее, деградацией не фармится;
   - рефилл работает заранее по low/high watermark, асинхронно — никогда
     синхронно в момент открытия игроком.

## Телеметрия v0 — четыре числа (SLO-доказательство, не персонализация)

размер unseen-runway · refill latency · число fallback-срабатываний ·
процент повторной выдачи.

## Пилот — самостоятельный продуктовый результат

Одна хорошо генерируемая механика, один approved-вариант: **100+ невиданных
серий, автоматический refill по watermark, ни одного пустого runway, ноль
ручных вкусовых решений после первоначального Approve.**

## Очередь (после переоценки 25.08)

`#151 → #136 piece 3 (hands-free) → #140 → пилот #159 → #118 s2/#109`.
Пилот не откладывается до персонализации: satiety/skill/теги остаются в
deferred-списке и включаются отдельными решениями поверх доказанной
бесконечности.

## Форма реализации: seed-гибрид (принято оператором 25.08)

Пилот #159 делается по форме «генератор внутри механики, authority на
сервере». Labs перестаёт быть конвейером серий и становится **редким гейтом
качества генератора**: один Approve на `{generatorVersion, envelope
параметров, difficulty-схема}` по репрезентативным и крайним seed — дальше
уровни внутри конверта появляются автоматически.

Контракт:

- Механика реализует чистую детерминированную функцию
  `generateLevel({generatorVersion, seed, difficultyIndex, approvedParams})
  → LevelSpec` (целочисленная/дискретная генерация — кросс-платформенная
  воспроизводимость обязательна). Предпочтителен конструктивный генератор
  (от решённого состояния обратимыми ходами) — решаемость by construction;
  иначе — предварительная сертификация блоков seed.
- Сервер выдаёт подписанные задания
  `{mechanicId, variant, generatorVersion, seed, difficultyIndex,
  parameterEnvelopeId}` блоками (runway = дешёвый запас seed, ~100–256
  вперёд); decision sidecar хранит то же + итоговый fingerprint.
- **Награды только за server-issued seed**; каждый выданный seed —
  одноразовый per-player (потребляется результатом); fingerprint-дедуп
  ловит коллизии разных seed в идентичные спеки.
- Деградация: клиент может продолжать играть на локальных seed, такие
  прогоны маркируются `local_degraded` и не дают экономических наград до
  сверки — hard-гарантия «лента не пустеет» сохраняется честно.
- **Правило апдейта клиента:** выданное задание пинит `generatorVersion`;
  обновление клиента не имеет права молча изменить смысл уже выданного
  seed — либо материализованный LevelSpec выданной партии сохраняется, либо
  задание переиздаётся под новую версию. Новый `generatorVersion` = новый
  вкусовой Approve (инвариант 2 без изменений).
- Общий пул (инвариант 1) вырождается в **сертифицированный seed-space**;
  персональными остаются seen-fingerprints, выданный runway, позиция
  сложности, результаты. Watermark по p10 заказывает новые
  сертифицированные диапазоны seed, а не ручное производство.
- Телеметрия v0 в seed-мире: unseen = выданные несыгранные seed; refill
  latency = латентность выдачи блока (≈0); fallback = число
  `local_degraded`-прогонов; повторная выдача = fingerprint-повторы.
  Плюс recall-паттерн по аномальному fail-rate на difficultyIndex —
  страховка от «монотонной по параметрам, но не по факту» сложности.

Границы неизменны: полностью клиентская фабрика (клиент сам решает, что
допустимо и награждаемо) — запрещена; verified-run/ticket-цепочка остаётся
единственным путём наград.
