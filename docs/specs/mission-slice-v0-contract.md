# Mission Slice v0 — execution contract (draft-for-decision)

Статус: **DRAFT** — ждёт пяти операторских решений §D; после них FROZEN.
Якорь: VISION.md (обещание игроку, impact-экономика, лестница §518,
non-goals §551). Слайс покрывает ступени 1→2 лестницы: founder dogfood
→ 3–10 друзей. Мораторий вижена соблюдён: это ЕДИНСТВЕННЫЙ новый
платформенный контур до прохождения ступени 2.

## A. Что доказывает v0 (и только это)

Один сидированный локальный кейс проходит полный честный цикл:
публикация с гарантированным подарком → игровой вклад сообщества
(сундуки серий → токены) двигает видимый прогресс → token goal →
церемония UNLOCKED → реальная передача → closure evidence → кейс в
истории. Игрок (сначала основатель, потом 3–10 друзей) понимает три
раздельных факта, не путает токены с деньгами, доверяет закрытию и
хочет вернуться.

## B. Поверхности игрока (макеты — canvas «Mission Slice v0»)

1. **Mission-бар над лентой** (постоянный, компактный): аватар кейса,
   токен-прогресс к цели, бейдж «помощь гарантирована платформой».
   Тап → кейс-шит.
2. **Кейс-шит**: фото/история кейса (без tragedy porn — тон §D4); ТРИ
   раздельных факта: «вклад сообщества: N/goal токенов» · «гарантировано
   платформой: <подарок>» · «передано: … / ещё нет»; ссылка «полный
   контракт» (формула, получатель, evidence-правила); объяснение петли
   «серия → сундук → токены → вклад».
3. **Сундук-момент**: к существующему сундуку серии добавляется
   токен-начисление и видимое движение mission-бара (та самая связка
   «игра двигает общее»).
4. **Церемония UNLOCKED**: token goal достигнут — праздник + фиксация
   «что открыто» (по §D3). Без ложной причинности: «сообщество открыло
   дополнительное», не «вы спасли».
5. **Закрытие**: passing evidence (фото передачи, дата, документ) +
   честный итог формулой результата («передали X корма»), вторая
   церемония. Кейс уходит в «Историю» (v0-монумент = простой список
   закрытых кейсов с личной пометкой «твой вклад: N токенов»).

## C. Контур (server-owned, default-off)

- Новый mission-контур по правилам Stage 0/1: публичные факты
  human-true; вклады только из НОВЫХ qualified-series/daily receipts
  (сундук завершённой серии = источник токенов; истор. балансы не
  конвертируются); append-only журнал вкладов с replay по seq;
  версионированные конфиги (token goal, начисление за сундук,
  unlock-правило); immutable receipts кейса (publication / UNLOCKED со
  снапшотом / closure с evidence-digest).
- Боты никогда не видны на миссионных поверхностях; вклад ботов = 0.
- Флаги default-off; включение — операторский акт на founder dogfood.
- Финансовой автоматики НЕТ: гарантированный подарок сидируется
  основателем вне системы (vision это явно разрешает и не маскирует);
  в v0 не строим pool/выручку — только честные тексты об этом.
- Не строим (non-goals + мораторий): второй кейс, decoration,
  виртуальный приют-карту, рейтинг доброты, покупку токенов, guilt-FOMO,
  ad-load ради impact.

## D. Пять операторских решений (нужны до заморозки)

- **D1. Партнёр и кейс**: какой локальный приют/животное; кто контакт;
  готов ли он к публичности evidence (фото передачи).
- **D2. Гарантированный подарок**: что именно и сколько («100 кг корма»
  класс — законченный, проверяемый результат) и бюджет основателя.
- **D3. Что открывает прогресс в v0**: (а) только церемония+начало
  передачи (минимально честно), (б) + сидированный stretch («при цели —
  дополнительно Y»), правило фиксировано заранее. Рекомендация: (б) с
  маленьким Y — иначе токены двигают только цифру.
- **D4. Тон и язык кейс-карточки**: утверждаем 3–4 фразы-эталона
  (макеты дают заготовки).
- **D5. Evidence-формат закрытия**: минимум = фото передачи + дата +
  подтверждение получателя? нужен ли чек/документ в v0.

## E. Сборка и порядок

1. Backend mission-контур (журнал вкладов от chest-receipts, конфиги,
   receipts кейса, read-проекции) — Codex A после correction batch;
   Tier-2 (новый контур), миграция — отдельный GO.
2. Feed-поверхности (бар, шит, сундук-связка, церемонии, история) —
   Codex A следом; dogfood-tier UI + браузерные проверки.
3. Контент кейса (фото, тексты по D4) — оператор + я.
4. Founder dogfood по ступени 1 → фиксация exit/kill наблюдений →
   решение о ступени 2 (3–10 друзей, launch kit готовит Fable).
Оценка: backend 2–3 дня + feed 2–3 дня после батча; календарно ~неделя
до founder dogfood при свободной полосе Codex A.

## F. Метрики и стоп-условия (ступени 1–2)

Из лестницы: понятность трёх фактов без объяснений; отсутствие «я
пожертвовал деньги»; доверие закрытию («верю, что передали»); желание
вернуться за новой серией/кейсом без пинга. Kill: устойчивые
«непонятно/не верю/давит» после честных итераций. Числовые пороги —
только со ступени 3 (30–50), в v0 не фиксируем.
