# Market Researcher: charter R0/R1

Статус: **FROZEN v1.1** (операторские решения 21.08.2026; поправки
Codex-ревью 21.08 приняты: закрепление credentials за Mac A, скрытый ввод
токенов, source-policy манифесты, честная оценка reference pack) для R0/R1;
R2/R3 — направление, не authority. Роль поднимает существующую ручную
дисциплину `docs/mechanics/` (каталог классов, `CLASS-BRIEF-TEMPLATE`,
`REFERENCE-REPLICATION-PROCESS` v3, `REFERENCE-DEVICE-LAB`) до
автоматизированного входа; она не заменяет и не обходит их.

## Принцип

**Широкий read, узкий write, нулевой execution authority.**
Агент изучает источники и собирает evidence; он не выбирает механику
окончательно, не запускает копирование, не публикует, не скачивает и не
исполняет чужой код, не выдаёт оценки источников за факты. Model verdict —
никогда не authority: решение всегда одно операторское касание.

## Продукт роли

1. **Shortlist** — 5–7 дедуплицированных кандидатов из 20–30 наблюдений,
   каждый с evidence (источник, дата, регион, momentum, метрики).
2. **Reference pack** (на выбранных) — содержимое по
   `REFERENCE-REPLICATION-PROCESS`: геймплей-записи, правило-вариант,
   тайминги/easing/feel, win/fail/restart/hint, первые 10–15 секунд,
   parity-чеклист ~20 наблюдаемых свойств, отделение механики от брендинга
   и trade dress. Числовой бриф вместо «сделай как в видео» — главный
   рычаг сокращения polish-итераций.
3. Один тап оператора «Копировать» → обычный durable mechanic-ticket.

## Scorecard v0 (versioned; правится receipt'ами, не в голове)

Оси (0–3 каждая, без сводного «магического балла» — профиль важнее суммы):
рыночный momentum (рост, не абсолют) · сила закупки (масштаб/длительность
кампаний) · web/playable-валидация (чарты Poki-класса, YT plays) ·
механическая ясность (правило выделяемо и формализуемо) · fit ленты
(portrait, autoplay-съёмность, сессия ≤60с, takeover-совместимость) ·
фабричность (уровни генерируемы солвером) · пробел каталога (класс из
docs/mechanics ещё не покрыт) · риск trade dress (ниже = лучше) ·
стоимость эталона (прогноз по PROCESS-RECEIPT прошлых классов).

## R0 — первая партия (моя)

Без нового сервиса и БД: Tier-A публичные источники + ST API (по получении
токена) → 20–30 наблюдений → scorecard → shortlist 5–7 → **два lite
reference pack** (правило-вариант, ключевые тайминги, публичные записи) →
операторский выбор → **один full reference pack** по выбранному
(полный `REFERENCE-REPLICATION-PROCESS`). Оценка: shortlist+lite — 1–2
дня; full pack — P50 2–4 дня и делается один раз по выбору, не заранее. Артефакты: в meta
`docs/research/2026-08-<batch>/` (метаданные, digests, выводы; сырые
платные выгрузки и видео — локально, в git только разрешённое).

## R1 — Research Radar в Labs (Mac B, 2–4 дня, после S1 E2E/S3)

Не четвёртая комната: **путь в комнате «Создать»**:
Рынок → Радар → Shortlist → Reference pack → Выбран → В разработке →
Кандидат в dev-ленте → Принят/Отклонён.
Статусы `observed / shortlisted / reference_ready / selected / rejected`;
действия «Копировать» (создаёт durable mechanic-ticket), «Позже»,
«Неинтересно» (причина возвращается в scorecard). Реализация по этому
frozen charter; Tier-1 ladder Mac B.

## R2/R3 — направление (не authority)

R2: адаптеры (ST MCP/API, AppMagic по итогам маркетинга, YT-полка и
device-capture по `REFERENCE-DEVICE-LAB`, нормализация/дедуп). R3:
регулярность ТОЛЬКО как model-free snapshot → детерминированный
change-detector → bounded run при материальном сигнале (зеркало #136);
безусловный LLM-таймер запрещён. Активация R3 — отдельное операторское
решение после 3–5 ручных партий.

## Метрики успеха

Оператор разбирает недельный shortlist ≤10 минут · 3–5 настоящих
кандидатов из 20–30 наблюдений · первый кандидат выбранной механики
требует ≤1–2 содержательных polish-циклов · сокращается
`selected → playable in dev feed` · причины отклонений улучшают следующий
поиск.

## Границы

Никаких: автокопирования, публикаций, скачивания/запуска чужого кода,
новых демонов, credentials в git, browser-автоматизации там, где есть
API/MCP. Finance v1-B остаётся PARKED (решение 21.08).
