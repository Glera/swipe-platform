Комнаты — слой навигации и группировки НАД существующими view. Ни один
экран не переписывается, ни один роут/тест-контракт не меняется. Поведение

## Требования

1. **Шапка**: первый ряд — три кнопки-комнаты (название, короткий саб,
   агрегированный счётчик); второй ряд — вкладки активной комнаты. Вкладки
   сохраняют свои `data-view-button` и идентификаторы view БЕЗ изменений —
   существующие lab-ui тесты обязаны пройти без правок (клик по
   `data-view-button` из теста работает независимо от активной комнаты:
   при программном/тестовом `setView` комната активируется автоматически
   по карте выше).
2. **URL**: `?room=review|pipeline|prod` добавляется к существующему
   `?view=…`; старые deep-link с одним `?view` продолжают работать — room
   выводится из view по карте. Последняя вкладка каждой комнаты
   запоминается (localStorage) и восстанавливается при входе в комнату.
3. **Клавиши 1/2/3** переключают комнаты. Гард: не срабатывать, когда фокус
   в input/textarea/select/contenteditable; проверить отсутствие коллизий с
   существующими хоткеями отсмотра (J/S/L/B и стрелки).
4. **Поллинг**: переиспользовать логику интервалов волн 3–4 без изменений;
   смена комнаты просто вызывает setView её текущей вкладки.
5. **CSS**: стиль комнат — по духу прототипа (тёмный, lime-акцент), без
   редизайна остального.
6. **Тест**: один новый lab-ui тест — переключение комнат, deep-link
   `?view=…` активирует правильную комнату, клавиша не срабатывает в
   фокусе поля ввода. Существующие тесты — зелёные без ослаблений.
