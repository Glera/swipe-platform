# auto-review

Запускается из авторской сессии **перед commit/PR**. Прогоняет полный patch
(`base → working tree`) через независимого ревьюера, который слеп к автору, но
не к кодовой базе, и заставляет автора закрыть каждое finding явной
диспозицией. Спецификация: `docs/specs/dev-loop.md`, раздел **WS2**.

## Инварианты (обеспечены скриптом — не обходить)

- **Авторский worktree read-only.** `scripts/auto-review-collect.mjs` НИКОГДА
  не пишет в исходный репо/index; вся сборка идёт в одноразовом detached
  worktree под temp. Падение любого шага не меняет исходное дерево.
- **Secret guard fail-closed** и **лимит diff 300 KB** уже реализованы в
  скрипте. Секреты не попадают ни в reviewer-материалы, ни в checkout.
- **Транскрипт — не evidence.** Sanitized transcript ревьюеру НЕ передаётся;
  раскрытие плана/объяснений автора допустимо только *после* слепого раунда и
  только для разрешения спорных findings.

## Цикл v1 (шаги 1–6)

### 1. Собрать patch identity + изолированный checkout

Из корня meta-repo:

```
node scripts/auto-review-collect.mjs [--allow-large-binary <path>]... <путь-к-репо>
```

Untracked-бинарники > 5 MB исключаются fail-closed (reason `size`); если
конкретный крупный бинарник заведомо нужен ревью — явно пропустить его флагом
`--allow-large-binary <repo-относительный-путь>` (повторяемый; фиксация — в
манифесте, поле `allowedLargeBinaries`).

Скрипт печатает JSON-манифест в stdout и оставляет изолированный checkout
живым для ревьюера. Коды выхода: `0` ок; `2` — суммарный текстовый diff > 300 KB
(сузить scope: застейджить/закоммитить меньше, разбить изменение, исключить
генерируемые файлы — и повторить); `1` — прочие ошибки.

Прочитать также опциональный `<repo>/REVIEW-INVARIANTS.md` — он передаётся
ревьюеру как authoritative-контекст, если существует.

### 2. Прочитать манифест

Из JSON извлечь:

- `base`, `upstream`, и — если присутствует — `baseFallback: "local-master"`
  (**зафиксировать в резюме**: база не от настроенного upstream);
- четыре слоя: `layers.commits` (sha+subject), `layers.staged`,
  `layers.unstaged`, `layers.untracked`;
- `binaryManifest` (`{path, layer, size, sha256}` — содержимое бинарников в diff
  НЕ идёт, но реальные байты уже в checkout; `layer` = слой этой записи);
- `excludedSecrets` (`[{path, reason}]`, где `reason` ∈ `name|content|size` —
  перечислить в резюме);
- `allowedLargeBinaries` (крупные бинарники, явно допущенные флагом
  `--allow-large-binary` — перечислить в резюме, если непусто);
- `secretsOmittedFromCheckout: true` (секреты отсутствуют и в checkout);
- `checkoutPath` — корень изолированного checkout для ревьюера;
- `diffPath` — путь к файлу полного текстового diff всех слоёв (передаётся
  ревьюеру на шаге 3);
- `diffBytes` — размер текстового diff.

### 3. Вызвать независимого ревьюера (subagent, свежий контекст)

Запустить **отдельного** ревьюера-субагента, **строго слепого к автору**.
Передать ему ТОЛЬКО:

- путь изолированного checkout (`checkoutPath`) — работать **read-only**;
- полный текстовый diff patch из файла `diffPath` (все слои, с заголовками
  секций) и список слоёв из манифеста;
- `<repo>/REVIEW-INVARIANTS.md`, если существует;
- явное указание: доступны полные затронутые файлы, их callers/consumers,
  связанные тесты, authoritative docs и соседние контракты — всё **внутри
  checkout**; ничего не писать, не запускать мутаций.

**НЕ передавать** транскрипт, план и объяснения автора.

Требуемый формат вывода findings — нумерованный список, каждый пункт:

```
N. [P1|P2|P3] <файл>:<строка> — краткое описание проблемы и почему это баг/риск
```

Серьёзность: **P1** блокер/корректность, **P2** значимо, **P3** мелочь/стиль.

### 4. Присвоить run-local ID

Каждому finding присвоить стабильный внутри прогона ID `F001`, `F002`, …
(стабильность между LLM-прогонами не обещается). Вести таблицу
`ID → severity → файл:строка → описание`.

### 5. Диспозиция по КАЖДОМУ ID

Для каждого `F###` — ровно одно из двух:

- **исправить** в авторском worktree (правки делает автор, не ревьюер и не
  в checkout); либо
- **явно отклонить** с причиной.

**Молчаливый пропуск запрещён.** Вести findings и диспозиции в JSON вида
`{findings:[{id,severity,file,line,desc}], dispositions:[{id, action:"fixed"|"rejected", reason?}], verify:[...]}`
(секция `verify` заполняется на шаге 6; механическая валидация всего файла —
там же, после повторных проверок). Спорные findings — раскрыть ревьюеру
план/контекст (после слепого раунда) и до-разрешить.

### 6. Повторить проверки, провалидировать, собрать резюме

Повторно прогнать **verify-команду затронутого репо** (из `AGENTS.md`,
колонка `verify`) и записать команды с их exit codes в секцию `verify` того же
JSON: `verify: [{command: "<команда>", exitCode: <целое>}]` (минимум одна
запись).

Затем прогнать валидатор над полным JSON
(`findings` + `dispositions` + `verify`):

```
node scripts/auto-review-validate.mjs <dispositions.json>
```

Он падает (exit 1) при: malformed ID (не `^F\d{3,}$`), невалидных полях
finding (severity ∉ {P1,P2,P3}, пустой `file`/`desc`, `line` < 1),
пропущенном/лишнем/дублирующемся ID, `rejected` без `reason`, отсутствующей
или пустой секции `verify`. **Резюме формируется только после зелёного
валидатора (exit 0).**

Сформировать **Markdown-резюме**:

- список findings (`F###`, severity, файл:строка, описание);
- по каждому: **принято** (что исправлено) или **отклонено + причина**;
- verify-команды и их exit codes;
- при fallback — пометка `baseFallback: local-master`;
- перечень `excludedSecrets` (если непусто).

Резюме идёт в **PR description или task output — НЕ в commit message**
(там оно быстро распухнет). В PR опционально — hash-ссылка на sanitized
transcript и краткая статистика.

### Финал: удалить checkout

```
node scripts/auto-review-collect.mjs --cleanup <checkoutPath>
```

Удаляет изолированный worktree (`git worktree remove --force` от имени
исходного репо) и его temp-директорию.

## Не делает в v1

Receipt-схему, task-store, межсессионный роутинг, авто-редактирование PR.
Второй ревьюер (Codex CLI) — не в каждом прогоне; на части пилотных patches
сравнить Claude vs Codex по дополнительным findings, затем решать.
