# Независимое ревью R5: mobile-first Lab review queue

Дата: 2026-07-29. Ревьюер: Claude + три адверсариальных Opus-агента.
Автор ≠ ревьюер. Круги: R1 → R2 → R3 → R4 → R5.

Head-и (совпадают с SHA зелёных CI — проверено буквально): backend `6a526ac`,
feed/TMA `fd7c6b1`, generator `c8cc533`, agents `c69f5a8`.
Ничего не мержилось и не деплоилось.

## Вердикт: **NO-GO**, но контурная безопасность закрыта по-настоящему

**Главное достижение круга: класс «побег из песочницы» закрыт на обоих
движках, и закрыт по конструкции, а не по добросовестности артефакта.**

Механизм проверен адверсариально (42 вектора × 4 конфигурации × Chromium 145 /
WebKit 26):

| Конфигурация | Chromium | WebKit |
|---|---|---|
| прод (bridge в байтах + `csp`-атрибут) | **0/42** | **0/42** |
| только bridge в байтах | 0/42 | **0/42** |
| только `csp`-атрибут | 0/42 | **27/42 утечка** |
| контроль (ничего) | 24/42 | 27/42 |

То есть `iframe[csp]` действительно работает в Chromium и **полностью
игнорируется WebKit** — и на WebKit единственной политикой остаётся та, что
лежит внутри хэшированных байтов. Ключевое: **backend её жёстко требует** —
байт-точный 690-байтный frozen bridge сразу после канонического doctype, ровно
один раз. Тринадцать вариантов ослабления (bridge отсутствует, внутри `<head>`,
после пробела, после комментария, дважды, `default-src *`, только meta, только
скрипт, переставленный, маркер-обманка в комментарии, лишний маркер в `<body>`)
— все отвергнуты. Артефакт без политики физически не может быть принят.

Закрыто также: R4-B1 (33-кейсовая батарея префиксов, все принятые формы дают
`CSS1Compat` на обоих движках), R4-B2 по механизму (один запрос, `srcdoc` —
подменить нечего), R4-B3 (403/302/снятый CSP больше не дают `configured`;
навигация до первого `load` детектируется). В generator закрыты все три моих
R4-находки; backend закрыл `except DBAPIError` 5 из 5 и **честный drift-гард**
(проверено в обе стороны). В feed закрыты оба инертных пункта одной осмысленной
ассертой (close-page/new-page, цепочка A→B→A).

Блокирует пять пунктов — и все они теперь про **доказательства и надёжность**,
а не про утечки.

## Блокеры R5

### R5-B1 · P2 · `prototype_review` не передаёт доказательство вообще
Для того самого класса ревью, ради которого существует песочница, решение
содержит только `{schema, verdict, comment}` — контракт запрещает любые другие
ключи. У бэкенда **нет записи**, что превью вообще запускалось: ни
`preview.configured`, ни привязки к дайджесту артефакта, ни факта блокировки.
Единственный гейт — клиентский булев флаг, инициализированный в `false`.
Воспроизведено: при удерживаемой загрузке артефакта клик «Перспективно»
немедленно сохраняет вердикт.

Соседний `experiment_review` несёт `preview.configured` + дайджест с серверной
проверкой членства. Нужно привести `prototype_review` к тому же виду и
записывать факт блокировки (сейчас он не доезжает до append-only следа вовсе).

### R5-B2 · P2 · Честный прототип обвиняется в побеге (дедлайн 750 мс)
Дедлайн квитанции — жёсткие 750 мс от `load`, гонка с **собственным main
thread артефакта**. Воспроизведено: прототип, занятый 1100 мс на сборке
уровня/декоде ассетов, без единого сетевого запроса, получает уничтожение
iframe и отказ в решении с текстом «Этот preview нарушил sandbox». На
CPU-throttled телефоне это вероятный сценарий для любой реальной игры.
Восстановление есть (перекликнуть вкладку превью), но недискаверабельно.
R4-N4 не закрыт — ложное обвинение переехало с `reload` на занятый поток.

Нужен liveness-хендшейк (периодический re-challenge) вместо одного дедлайна,
формулировка «прототип не отвечает — повторить» вместо обвинения, и явная
кнопка повтора после блокировки.

### R5-B3 · P2 · Нет unmount: устаревший mount портит другой бандл
`renderView` не разбирает предыдущее превью: слушатель `message` остаётся на
`window`, таймер 750 мс тикает, незавершённый fetch продолжается, и все mount-ы
пишут в одну и ту же внешнюю переменную. Воспроизведено: поздний отказ
доставки артефакта бандла X, когда оператор уже на проверенном бандле Y, гасит
решение Y с текстом про нарушение sandbox.

### R5-B4 · P2 · Один транзиентный 503 выбрасывает совершённый Approve (generator)
Ретрай публикации перекручен в противоположную крайность: любая ошибка ставит
блокировку attempt-а навсегда. Воспроизведено: 50 тиков → **один** вызов
token-эндпоинта, `publish = 0`, статус остался `pending`, `failure = null`.
Планировщик опрашивает каждые 5 c всё окно device-flow (300–900 c, то есть
60–180 запросов) — достаточно одного 503, чтобы уже совершённый человеком
Approve был выброшен, а оператору выдана чистая карточка без причины. Тест
кодифицирует нулевой ретрай буквально.

Это прямо против замороженного решения оператора («после Approve
server-owned scheduler может завершить доставку без открытого браузера и
второго клика»). Нужен ограниченный ретрай с backoff для класса «продолжение»,
терминализация только после исчерпания попыток, и видимый оператору признак
«флоу застрял» вместо `pending / failure: null`.

### R5-B5 · P2 · Фантомы всё ещё глушат живые алерты (agents)
Фикс бюджета отправок пропатчил `realTransportSendsInWindow`, но не
`otherSendableCount`, который считает конкурирующей нагрузкой любую строку в
неопределённом состоянии. Воспроизведено **без инъекции ошибок**: недоступность
Telegram исчерпывает попытки у 20 инцидентных доставок (0 HTTP), Telegram
возвращается — настоящий инцидент терминально гасится, бюджет посчитан нулевым.
На боевом конфиге 45 фантомных строк гасят все три живых review-пинга.

Сопутствующее (P2): любая ошибка рендера после исчерпания попыток даёт
терминальную строку, но дедупликация и восстановление пропущенных доставок
смотрят на существование строки **без фильтра по статусу** — значит
инцидентный сигнал, единожды терминализованный, не переставится **никогда**;
право на переотправку спека выдала только production-action. Видимый затык
заменён тихой потерей, включая саму breaker-сводку.

## Незакрытые несущие границы (две независимые находки совпали)

Два агента, работавшие изолированно, независимо обнаружили одно и то же:

- **проверка «байты соответствуют заявленному дайджесту» не закреплена ничем** —
  её можно удалить, и вся приёмка (включая PG-набор) остаётся зелёной; в модели
  нет и CHECK, связывающего байты с дайджестом. Content-addressing — фундамент
  схемы — держится только на том, что код сейчас написан верно;
- **вызов `_validate_mobile_review_bridge` можно удалить с пути загрузки** —
  frozen bridge проверяется только как чистая функция; ни один тест не грузит
  артефакт без bridge. То есть защита, на которой стоит вся WebKit-безопасность,
  не закреплена на своём пути;
- **родительский `frame-src` — единственная защита от URL-эксфильтрации** (CSP
  не имеет директивы против self-navigation), и он **не покрыт**: при мутации
  этой одной строки 5 навигационных векторов утекают на сторонний хост на обоих
  движках;
- окно TTL тикета не проверяется (принимаются истёкшие и «из будущего»);
  membership при redeem инертен; signed URL продолжает отдавать байты после
  вытеснения бандла; старый роут отдаёт любой артефакт по дайджесту.

Плюс **два слоя политики маскируют друг друга**: удаление `csp`-атрибута и
удаление meta из тестовой фикстуры по отдельности **не краснеют**, потому что
на Chromium каждый прикрыт другим. Сьют физически не может заметить потерю
WebKit-защиты. И 45-документный корпус из R4 проверяет доставку через
`frame.src` с заголовком — путь, которым прод больше не пользуется.

**В CI нет WebKit вообще**: 20 Playwright-скриптов, все `chromium`; workflow
устанавливает только `chromium`. Оператор при этом ревьюит с iOS, то есть
именно на WebKit. Отдельно измерено: заблокированная попытка побега на WebKit
**неотличима от здоровой перезагрузки** — предупреждение «прототип попытался
покинуть sandbox» существует только в Chromium.

## Минимум для шестого круга

1. **WebKit-джоб в CI** — сейчас проверяется не тот движок, на котором работает
   оператор. Плюс разделить два слоя политики в тестах, чтобы потеря любого
   краснела по отдельности, и перенести 45-вектор­ный корпус на фактический
   `srcdoc`-путь.
2. `prototype_review` → те же `preview.configured` + дайджест + серверная
   проверка членства, что у `experiment_review`; факт блокировки записывать.
3. Дедлайн 750 мс → liveness-хендшейк с явным повтором; убрать обвинительную
   формулировку.
4. Реальный unmount из `renderView`.
5. Ограниченный ретрай с backoff для класса «продолжение» + видимый признак
   застрявшего флоу (требование замороженного решения).
6. Патч второго слагаемого бюджета (`otherSendableCount`); право на
   переотправку — для сигналов, не только production-action.
7. Закрепить несущие границы: digest↔байты (тест + CHECK), bridge на пути
   загрузки, родительский `frame-src`, TTL тикета, membership при redeem.
   Записать как принятый риск то, что решено не чинить (signed URL после
   вытеснения, старый роут по дайджесту).

Порядок включения после зелёного круга не меняется. Выдача
`operator.review:write` и переключение прод-уведомлений остаются операторскими
гейтами.
