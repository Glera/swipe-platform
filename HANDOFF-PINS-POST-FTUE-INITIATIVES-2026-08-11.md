1. **Ваш релиз в проде нетронут байт-в-байт.** Каждый пуш в `playables-export`
   проходил hook-сверку sha256 релизных `pins-ftue-l*.html` (394fadf, 23.07).
2. **`pins-ftue/src` менялся дважды, оба раза type-only** (см. §5, обоснование и
   одобрение оператора там): удалён `src/matter.d.ts` (теперь одна каноническая
   декларация `shared/matter.d.ts`) и добавлен `type PinDef` в импорт из
   `./levels` в `main.ts`. Рантайм-семантика нулевая, но **следующая пересборка
   FTUE слинкует `shared/matter.d.ts`** — учитывайте при диффах с тегом.
3. **Пересборка/редеплой FTUE теперь заблокированы гейтом.**
   `npm run build:ftue-levels pins-ftue` откажет без `FTUE_RELEASE_OVERRIDE=1`;
   коммит изменённых релизных байтов в export блокирует pre-commit hook.
   Процедура нового релиза: override → `test:ftue` (161) + device QA →
   обновить блок `deployed` в `ftue-release.json` → commit/push export.
4. **`shared/` дрейфанул после вашего тега** (analytics — двухфазный
   CHALLENGE_STARTED-автомат в bootstrap, haptics, sfx, mraid, quality,
   auto-cursor; ~130 строк на момент 06.08, дальше больше). Пересборка FTUE — это
   осознанный release cut с полным прогоном гейта, не «пересобрал и залил».
5. **Ваши ассеты не тронуты**: `pins-ftue/assets/source` (включая raw-мастера)
   на месте, в concept store НЕ мигрирован. Рекламные даунскейлы ушли в НОВЫЕ
   файлы `concepts/pins/source/*_sbs_ad.mp4` — ваши `*_sbs.mp4` без изменений;
   мастера читались только на чтение.
6. **Эндкарта/CTA-правки (§6) вас не касаются** — гард `__TARGET__ !== 'ftue'`;
   FTUE-контракт (ready/hide_hud/win/lose, PinsStart/PinsUsed) не менялся.
7. Незакоммиченная пересборка 28.07, лежавшая в рабочей копии export, отброшена

## 1. Фаза 0 — укрепление заморозки FTUE (коммит `d698156`)

**Почему:** заморозка держалась только на дисциплине: `build-ftue-levels.sh`
пишет НАПРЯМУЮ в `playables-export`, и 28.07 локальная пересборка уже
перезаписала рабочую копию релизных файлов (незакоммичено). Плюс `shared/`
дрейфанул после тега (~130 строк) — любая пересборка FTUE слинкует новый код.

**Что сделано:**
1. Рабочая копия `playables-export` откачена к задеплоенному HEAD
   (решение оператора: канон = задеплоенные байты; пересборка 28.07 отброшена,
   т.к. функционально идентична и её пуш был бы ненужным редеплоем).
2. В `ftue-release.json` добавлен блок `deployed` — точные sha256/байты
   задеплоенных файлов + канал + export-коммит.
3. Три линии защиты байтов:
   - `npm run check:ftue-export` (`scripts/checks/ftue-export-lock.mjs`) —
     сверка export-файлов с `deployed`-хэшами;
   - `build-ftue-levels.sh pins-ftue` отказывает без `FTUE_RELEASE_OVERRIDE=1`;
   - pre-commit hook в `playables-export/.git/hooks/pre-commit` блокирует коммит
     изменённых релизных байтов (гоняет lock-скрипт по staged).
   Осознанный новый релиз FTUE = override + обновить `deployed` + commit/push.
4. Доки: `PLATFORM_VARIANTS.md` (§Pins — канал, защита, предупреждение о shared/),
   баннер заморозки в `FTUE_RELEASE_GATE.md`.

**Остаточный риск (принят):** заморозка защищает байты, но не запрещает править
`pins-ftue/src` в git; пересборка возможна только через явный override.

## 2. Ветка `codex/platform-device-tier` (worktree `playables-pins-rollout`) — разбор и парковка

**Аудит показал:** ветка НЕ трогает pins-ftue (ранняя оценка была ошибочной);
её pins-swipe контент и `AD_NETWORKS.md` уже байт-в-байт на основной ветке.
Уникален только `f38ea14` — редизайн `shared/quality.ts`: свайп перестаёт
самобенчмаркаться (300ms busy-loop в скрытом iframe даёт ложный `low`,
залипающий в localStorage на 30 дней) и потребляет тир родителя через `?quality`.
**Патч — половина дизайна:** платформенная часть (замер в feed-клиенте + прокидка
в iframe URL) не реализована; принятие патча в одиночку опустило бы всех в
`standard`. **Решение оператора:** оставить как есть, ветку запарковать
(НЕ удалять — в ней живёт патч), доработку забрать в отдельную сессию.
Полный контекст: memory `swipe-platform-owned-tier-design`.

## 3. Concept store для пинов (коммиты `11d1726`, `6e91ba3`)

**Почему:** 4 pins-форка несли ~545MB дублированных ассетов; матрица добавила бы
ещё ×4. Стандарт «код форкается, тяжёлые ассеты общие» уже существовал
(`concepts/<name>/` + алиас `@concept`, эталон short-drama) — пины были легаси.

**Что сделано:** `npm run concept:extract pins-swipe pins` (база — pins-swipe:
его набор = полный 10-уровневый комплект build-входов, байт-идентичное
подмножество ftue-ассетов). Нюансы, важные для повторения на других механиках:
- скрипт уносит top-level `.mp4/.mov` в gitignored `masters/`, но у пинов это
  build-входы (SBS-деривативы) — возвращены в `source/` руками;
- скрипт удаляет ВЕСЬ `assets/` форка, включая `assets/generated/`
  (запечённые pinglow-PNG) — восстановлены из git; при форке новых вариантов
  `assets/generated` надо копировать руками (fork.sh их не копирует);
- **`pins-ftue` осознанно НЕ мигрирован** — замороженный форк остаётся
  самодостаточным (скрипт сам его пропустил как не-байт-идентичный);
- легаси `pins` (ad) перецеплен отдельно: его 6 «дрейфанувших» видео оказались
  устаревшими тяжёлыми энкодами до-07-08 (store-версии в ~2.5× легче), 15 файлов
  (.webm, dog-mp4, .DS_Store) кодом не импортировались — всё удалено с
  `pins/assets` (восстановимо из истории до `6e91ba3`).

## 4. Рекламная матрица `pins-ad-{applovin,unity}-{en,ru}` (коммиты `65ac5f7`, `376e78a`)

**Ключевое открытие, сложившее план на порядок дешевле:** портировать уровни в
устаревший легаси-`pins` (4 стейл-уровня) не нужно — `pins-swipe` уже несёт
релизный FTUE-контент всех 10 уровней (перенесён по документированной процедуре)
И сохранил всю ad-обвязку (CTA/analytics/endcard) за build-константами;
свайп-специфика вырезается DCE при `TARGET=applovin`. Форки сняты с pins-swipe.

- Конфиги: оси `surface/network/locale` (по `AD_NETWORKS.md`), боевые store URL
  из релизного timepress (Pines Peak: ios `id6743472188`, android
  `com.vizorapps.merge`), CTA `Play Now!`/`Играть!`, `dprCap 1.5` (ad fill-rate).
  Локализация = per-fork строки конфига; i18n-системы нет, внутриигрового текста нет.
- Шипятся **per-level** (`LEVEL=n` → `__LEVEL__` DCE), т.к. все 10 уровней в один
  5MB-файл не влезают физически.

**SBS-даунскейл (решение оператора: даунскейл, а не ослабление гейта):**
16 клипов персонажей (все серии кроме собаки L3/4) превышали ad-лимит габаритов
(длинная сторона ≤1920): 2688×768 (L1/2) и 2000×800/700 (L5–L10). Перекодированы
в `concepts/pins/source/*_sbs_ad.mp4` (CRF20, Main@4.1, lanczos; из FTUE-мастеров
где есть, loss L5–L10 — из деривативов; L1/2 → 1904×544, точный AR):
- принятый трейдофф: L1/2 −29% линейно (заметно), L5–L10 −4% (незаметно);
- бонус: −0.5…−1MB на уровень, запас к 5MB-капу вырос;
- FTUE и свайп остаются на полноразмерных оригиналах — импорты `_ad` только в
  4 ad-форках.

## 5. Проектный tsc-долг и ПРАВКА ЗАМОРОЖЕННОГО pins-ftue (коммиты `0e59f5c`, `fe6c206`, `bcb490b`)

**Почему трогали FTUE — главный вопрос этого handoff:**
`release.sh` гоняет `tsc --noEmit` по ВСЕМУ репо; 59 унаследованных ошибок типов
блокировали любой release, из них 7 сидели в `pins-ftue`. Причина неисправимости
точечно: 12 форков несли по копии `declare module 'matter-js'`, tsc брал одну
«выигравшую» декларацию — патчи в отдельных форках не работали.

**Решение оператора — вариант (c), явно одобрен с обоснованием:** один
канонический `shared/matter.d.ts` (+`translate`/`applyForce`/`Composite`),
9 пер-форковых копий удалены, **включая `pins-ftue/src/matter.d.ts`**, плюс
однострочный `type PinDef` в импорт `pins-ftue/src/main.ts`.

**Почему это безопасно для релиза (принятый риск):**
- правки type-only — рантайм-код не меняется вовсе;
- задеплоенные байты вообще не пересобираются (защита Фазы 0 это гарантирует);
- откат всегда возможен к тегу `9c01750` («комит релизного состояния есть,
  вероятность правки невысокая, неделю крутится в релизе без жалоб» — оператор);
- буква политики «не менять pins-ftue» нарушена осознанно ради духа репо
  («Shared runtime обязателен», Hard Rule 4).

Попутно: PinDef/`Item.chain` фиксы в pins/pins-v1/timepress-no-orders,
3 type-only фикса в **canonical-locked** `marble-sort-swipe` (.ts-расширения
импортов, каст sceneColors) → лок переутверждён коммитом `bcb490b` с записью
причины в `canonical/swipe-locks.json`. Итог: **0 ошибок tsc project-wide**.

## 6. Гейты, реальные баги и артефакты тестов (коммиты `8bf2b8e`, `917e461`, `685b22a`)

1. **Premium-FPS отскоуплен** (`8bf2b8e`): headless-хромиум декодит инлайн-H.264
   софтверно — видео-уровни давали 26–36fps при floor 45 независимо от CPU-троттла
   (×1→×4 почти не меняет цифру ⇒ упор не в CPU). Оператор замерил на iPhone:
   **стабильные 60fps и в Telegram WKWebView, и в контейнере AppLovin playablePreview**
   (QA-сборки с запечёнными `FORCE_TIER=premium` + `__ppPerf` лежат в
   `~/Desktop/pins-qa-perf/` — в ship не годятся, debug-хук запечён).
   Правило теперь: артефакт с `data:video/mp4` → premium-floor WARN@24;
   без видео → прежний FAIL@45. Арбитр перфа — device verify-preview.
2. **Дописан терминальный эндкарта-флоу** (`917e461`) — настоящий баг: ещё в
   легаси-pins `showCTA()` был закомментирован («MUST be restored before
   shipping to AppLovin»), свайп-линия завершала ран репортом хосту. Теперь:
   победа → досмотр win-видео → `sendWinCompletionOnce` → `showCTA()`
   (+`ENDCARD_SHOWN`); проигрыш → `report()` → `showCTA()`. Гард
   `!__SWIPE__ && __TARGET__ !== 'ftue'` — свайп/FTUE поведение не тронуто.
   Debug-хук `onWin` доводит до терминала сразу (идемпотентно) — иначе
   DEBUG_PROD-proof не дожидался конца видео.
3. **Тест `CHALLENGE_STARTED` ждёт реального снятия прелоадера** (`685b22a`)
   вместо фикс-паузы 2400мс — L7 (пять видеослоёв) в headless не успевал, тап
   уходил в пре-геймплей. Ждём удаления `#playable-preloader` (кап 15с).

**Итог гейтов:** полный `release.sh` зелёный на 4 ячейках × L1 + L7 (applovin-en)
+ L10 (unity-ru): статика сети, source policy, tsc, Playwright runtime
(в т.ч. Unity-специфика: MRAID 3.0 инжект, старт после first-viewable,
отсутствие клиентской аналитики), терминальный proof, offline, context-lost.
