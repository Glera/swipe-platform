# Гейт ontology на пути «сапёр в ростер» — доказательство по коду

- Дата: 05.08.2026. Ревьюер: Claude (Opus 5). Read-only, backend `0e9e940`.
- Запрос frontier: не принимать «нужно» или «не нужно» на слово, дать строку кода.

## Вердикт: гейта на фактическом пути НЕТ

Из трёх возможных исходов реализуется **второй**: гейт живёт только внутри
запаркованного sequencing-контура и на путь `feed_mapping_registry register
--apply` / `feed_roster register/activate --apply` не распространяется.

## Доказательство

**1. Модули ростера и реестра не знают про ontology вовсе.**

```
app/api_feed_roster.py               ontology: 0 вхождений
app/feed_mapping_registry.py         ontology: 0
app/feed_roster.py                   ontology: 0
app/feed_roster_console_contract.py  ontology: 0
```

Ни одного упоминания на все четыре модуля — ни импорта, ни проверки, ни
справочника.

**2. `mechanic_family` — простая строка без ограничений.**

`app/feed_mapping_registry.py:111`:

```python
mechanic_family: str
```

Поиск по модулю не находит ни `Enum`, ни `Literal`, ни перечисления
допустимых значений, ни регулярного выражения для этого поля. Значение
переносится в документ как есть (`:122`, `:299`, `:354`).

**3. Ontology живёт исключительно в sequencing-контуре, и он выключен.**

Упоминания сосредоточены в `feed_mechanic_ontology.py`,
`feed_sequencing_bootstrap.py`, `feed_sequencing_console.py`,
`feed_sequence_planner.py`, `feed_episode_materializer.py` и соседних. Флаг —
`app/config.py:232`:

```python
enable_feed_sequencing_ontology: bool = False
```

**4. Прецедент согласуется.** Регистрация pins-маппингов и активация ростера
28.07 прошли в проде без ontology-операций, и это ровно тот путь, который
предлагается для сапёра.

## Следствие для пакета

Заявление §4 сапёр-пакета — что добавление family `minesweeper` требует
reviewed successor-ontology PR и отдельного деплоя после фазы 4 — **не
подтверждается кодом на `0e9e940`**.

Сапёр едет коротким путём: mapping → roster entries → CAS activation, как pins
28.07. С критического пути снимаются целый backend-PR, его ревью, merge и
второй деплой.

Ontology-successor остаётся законным follow-up с формулировкой «перед
включением sequencing», а не предпосылкой цели «сапёр виден в ленте».

## Ограничение вердикта

Проверено чтением `0e9e940`. Фактический отказ или его отсутствие на dry-run
против восстановленной копии я не прогонял — если R1-A предъявит путь, где
гейт всё же срабатывает при реальных прод-флагах, это перекрывает вывод выше.
Но бремя доказательства теперь на утверждении «гейт есть», а не на отрицании.
